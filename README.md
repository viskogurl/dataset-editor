# Dataset Studio — Fresh on Deno Deploy

A Fresh 2 application for building, reviewing, moderating, importing, and
exporting prompt-response datasets. The browser editor is a Fresh island, and
OpenAI requests run through same-origin server routes so the API key is never
exposed to the client.

## Stack

- Fresh 2 with file-system routes and a Preact island
- Vite-powered Fresh development and production builds
- Deno 2 runtime
- OpenAI Node SDK through Deno's npm compatibility
- Plain CSS with responsive light and dark themes

## Project structure

```text
assets/styles.css          Global editor styles
islands/DatasetEditor.tsx  Interactive dataset editor
lib/dataset.ts             JSONL parsing and serialization
lib/openai.ts              Server-only OpenAI client
routes/index.tsx            Editor page
routes/chat-comp.ts         Generate a completion
routes/chat-mod.ts          Moderate a response
routes/format.ts            Format conversation text
static/                     Public assets
main.ts                     Fresh application entrypoint
```

## Run locally

Install Deno 2, then from this directory:

```bash
deno task setup
cp .env.example .env
```

Set `OPENAI_API_KEY` in `.env`. The included fine-tuned model IDs are the
defaults from the original application; replace them if those models are not
available to your OpenAI account.

Start the development server with the local environment file:

```bash
deno task --env-file=.env dev
```

Fresh will print the local URL. Changes under `routes/`, `islands/`, and
`assets/` reload during development.

## Checks

```bash
deno task check
deno task test
deno task build
```

The production server generated by the build can be run with:

```bash
deno task --env-file=.env start
```

## Deploy from the Deno CLI

Deno Deploy recognizes Fresh directly.

Create and configure the app interactively:

```bash
deno task deploy:create
```

Choose the **Fresh** framework preset and this project directory. Then add the
required secret and optional model overrides:

```bash
deno deploy env add OPENAI_API_KEY "sk-..." --secret
deno deploy env add OPENAI_COMPLETION_MODEL "your-completion-model"
deno deploy env add OPENAI_FORMAT_MODEL "your-format-model"
deno deploy env add OPENAI_MODERATION_MODEL "omni-moderation-latest"
```

Deploy the current directory to production:

```bash
deno task deploy
```

If you manage multiple Deploy apps, select the default first or pass the app
explicitly:

```bash
deno deploy switch --org your-org --app dataset-studio
deno deploy --org your-org --app dataset-studio --prod
```

## Deploy from GitHub

For the simplest setup, keep this application at the repository root.

1. Push the project to GitHub.
2. Open `https://console.deno.com` and create an organization and app.
3. Select the GitHub repository. Deno Deploy should detect the Fresh preset
   automatically.
4. Keep the detected install/build/runtime settings. If entering them manually,
   use `deno install` and `deno task build` with the Fresh framework preset.
5. Add `OPENAI_API_KEY` as a secret for both Production and Development
   contexts.
6. Add model overrides as plain variables when needed.
7. Create the app. Subsequent pushes to the linked repository trigger new builds
   automatically.

## Environment variables

| Variable                  | Required | Purpose                                               |
| ------------------------- | -------- | ----------------------------------------------------- |
| `OPENAI_API_KEY`          | Yes      | Server-side OpenAI authentication. Store as a secret. |
| `OPENAI_COMPLETION_MODEL` | No       | Model used by `GET /chat-comp`.                       |
| `OPENAI_FORMAT_MODEL`     | No       | Model used by `POST /format`.                         |
| `OPENAI_MODERATION_MODEL` | No       | Model used by `POST /chat-mod`.                       |

Never place the API key in client code or commit `.env`; local environment files
are ignored by Git.

## Dataset formats

The editor accepts newline-delimited JSON in either format:

```json
["user prompt", "assistant response"]
```

or OpenAI messages format:

```json
{
  "messages": [
    { "role": "system", "content": "..." },
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ]
}
```

Exports are available in both the editable pair format and OpenAI messages
JSONL.
